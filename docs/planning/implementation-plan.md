## 2. 总体目标

用 React、FastAPI、PostgreSQL 和 DeepSeek 建设可真实操作的招聘平台，先完成招聘业务闭环，再接入综合 Agent、RAG、权限和交付能力。

```text
基础平台
  -> 简历上传与结构化
  -> 岗位与 Application
  -> AI 初筛与 HR 决策
  -> 公开投递与异步处理
  -> 面试、Offer、录取
  -> 综合 Agent
  -> RAG
  -> 权限、部署和交付
```

## 3. 阶段门禁

每个阶段进入业务开发前必须完成：

1. 业务目标、用户场景、主流程和异常流程讨论。
2. 包含范围、不包含范围和前后阶段依赖确认。
3. 数据字段、状态、权限、API 和失败语义确认。
4. 自动化测试、真实集成和人工验收场景设计。
5. 独立阶段设计文档。
6. 用户明确确认。

任何会改变核心流程、数据模型、阶段边界或验收标准的需求，必须先回到文档门禁。

## 5. 当前跨阶段整改顺序

阶段 7 已完成旧 Rubric 清理、Application/Resume 隔离、异步运行、React 报告、固定投递时间和 HR 决策底座。3.0 与 4.0 均留下可复核历史，其中 4.0 的六份定向 HR2 为 6/6，但正式 20 份只有 15/20，证明原子事实拆解和归组仍会随 JD 变化产生大量专项整改。用户已经重新确认：阶段目标是可用的 AI 初筛，不是极细 JD 拆解；当前改为 5.0 轻量评价清单。

当前顺序调整为：

1. 6R-A 已完成：测试固定五字段、开放校验、旧字段退出和阶段 7 安全暂停合同。
2. 6R-B 已完成：后端与 PostgreSQL Job 合同原子切换，旧 JobEvaluationPlan 读取新 Job 的入口被阻止。
3. 6R-C 已完成：React 岗位表单、列表和现有读取方切换到五个大型文本框。
4. 6R-D 已完成：后端/前端全量、真实 PostgreSQL、真实 API、Microsoft Playwright 三档浏览器验收和阶段 7 交接通过。
5. 3.0 的 7R-A—7R-E 已完成，7R-F 定向真实质量失败；旧结果保持为历史证据，不继续执行旧 7R-G/H。
6. 4.0 的 7R4-A—7R4-H2 已结束并保留历史；正式 20 份为 15/20，7R4-I/J 不再继续，也不通过追加样本特例整改恢复。
7. 5.0 业务合同已经逐项确认：完整 JD、通常约 5—12 个 HR 可编辑评价点、每项 0—10、AI 直接总体 0—100、无权重、每名候选人独立、阶段 7 小批量最多 5 人。
8. 当前唯一下一步是用户整体确认 7R5-A—7R5-J 顺序；确认后只执行 7R5-A 合同测试与离线基线，后续每批继续单独确认。
9. 7R5-H 完成全部零调用门禁后才能展示官方价格并请求金额确认；7R5-I 才允许真实计划、报告和稳定性调用；通过后 7R5-J 完成真实 PostgreSQL/API/浏览器收尾。

5.0 实施和验收完成前，不得以 3.0、4.0、部分 5.0 或 Fake/Mock 结果冒充当前阶段完成；历史计划与报告只读，新筛选最终必须使用当前合法的 5.0 ready 计划。

## 6. 跨阶段依赖

- 阶段 7 依赖阶段 4—6 的 Resume、结构化草稿和五段式 Job；当前必须先确认 7R5-A—7R5-J 顺序，并依次完成 A—H 的程序与零调用门禁，才能在独立金额确认后进入 7R5-I。
- 阶段 8 复用阶段 7 的 Application、评价计划和报告引擎，再增加公开投递与持久化队列。
- 阶段 9 从 HR 已通过的 Application 开始面试、Offer 和录取流程。
- 阶段 10 通过受控 Tool 复用既有 Service，不复制业务规则。
- 阶段 11 复用 `raw_text/parsed_snapshot` 和权限边界，不改变正式初筛口径。
- 阶段 12 对完整主链补充认证、授权、审计、部署和端到端验证。

## 7. 每个小步骤的完成标准

每个开发小步骤至少说明：

1. 修改了哪些文件，各自承担什么职责。
2. 位于“前端 -> API -> Schema -> Service -> Model -> PostgreSQL”哪一层。
3. 自动化、构建、真实数据库或浏览器中的验证方法与结果。
4. 验证能够证明什么、不能证明什么。
5. 是否改变当前阶段设计；若改变，是否先更新文档并获得确认。
6. 简历中如何如实表达，以及面试官可能追问什么。

## 8. 全产品完成标志

- HR 能创建岗位并接收投递。
- 简历能够可靠保存、提取、结构化和进入对应岗位初筛。
- AI 报告可解释、可定位证据且不替代 HR 决策。
- Application 能推进到面试、Offer 和最终结果，并保留审计历史。
- 综合 Agent 只能通过受控 Tools 使用真实业务能力。
- 公司知识问答和简历语义搜索返回可追溯来源。
- AI、队列或外部服务失败不丢失业务事实和旧成功结果。
- 未授权用户不能访问内部数据或执行高风险操作。
